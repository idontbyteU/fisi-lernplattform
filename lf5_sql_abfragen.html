🔤 Grundvokabular: Statement, Klausel, Operator

Bevor es losgeht — die drei Ebenen, aus denen jede SQL-Anweisung besteht:

Statement = ganzer Satz. Eine vollstaendige Anweisung, endet mit ; (z. B. SELECT ... FROM ...;).

Klausel = Satzteil. Ein benannter Abschnitt innerhalb des Statements, kann nicht allein stehen (z. B. WHERE ..., GROUP BY ...).

Operator / Funktion = Wort im Satzteil. Das kleinste Bauteil, das Werte vergleicht oder verarbeitet (z. B. >=, LIKE, SUM()).

Merksatz: "Statement = Satz, Klausel = Satzteil, Operator = Wort."

🧭 Sprachsektionen: DDL, DML, DQL, DCL, TCL
Zu welcher Sektion gehoert SELECT?▶
DQL — fragt Daten nur ab, aendert nichts.
Zu welcher Sektion gehoert CREATE TABLE?▶
DDL — aendert die Struktur, nicht die Daten.
Zu welcher Sektion gehoert GRANT?▶
DCL — vergibt Rechte.
Zu welcher Sektion gehoert INSERT?▶
DML — fuegt Datensaetze ein.
Zu welcher Sektion gehoert DROP?▶
DDL — loescht Struktur (Tabelle/Datenbank), nicht einzelne Datensaetze.
Zu welcher Sektion gehoert REVOKE?▶
DCL — entzieht Rechte.
Zu welcher Sektion gehoert UPDATE?▶
DML — aendert bestehende Datensaetze.
Zu welcher Sektion gehoert COMMIT?▶
TCL — schliesst eine Transaktion ab.
Typischer Fehler: DROP (DDL — loescht die ganze Tabelle) mit DELETE (DML — loescht Datensaetze) verwechseln.
DDL = Struktur · DML = Daten · DQL = Abfrage · DCL = Rechte · TCL = Transaktion
🧱 Datentypen entscheiden
Welcher Datentyp fuer einen Artikelpreis?▶

→ DECIMAL(10,2): exakt, ideal fuer Geldbetraege.

Typischer Fehler: FLOAT/DOUBLE bei Geld.

Merksatz: "Geld = DECIMAL, Messwerte = FLOAT."

Welcher Datentyp fuer die Anrede (Herr/Frau/Divers)?▶

→ ENUM('Herr','Frau','Divers'): feste Werteliste.

Typischer Fehler: VARCHAR statt fester Auswahl.

Merksatz: "Feste Werteliste = ENUM."

Welcher Datentyp fuer eine Postleitzahl?▶

→ CHAR(5): feste Laenge, fuehrende Null bleibt.

Typischer Fehler: INT statt Text.

Merksatz: "Ziffern ≠ Zahlen: Wird nicht gerechnet, ist es Text."

Wie speicherst du den letzten Aenderungszeitpunkt eines Datensatzes automatisch?▶

→ TIMESTAMP mit DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP.

Typischer Fehler: manuell per UPDATE pflegen.

Merksatz: "Zeitstempel automatisieren, nicht pflegen."

Welcher Datentyp fuer eine lange Artikelbeschreibung?▶

→ TEXT (bis 65535 Byte).

Typischer Fehler: VARCHAR(255).

Merksatz: "VARCHAR = kurze Angaben, TEXT = Fliesstext."

🔗 Constraints & Fremdschluessel

Die Tabelle artikel mit Primaerschluessel, Index und Fremdschluessel auf kategorie:

CREATE TABLE IF NOT EXISTS artikel(
  artikelId INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,   -- PRIMARY KEY/UNIQUE erzeugen automatisch einen Index
  artikelName VARCHAR(75) NOT NULL,
  beschreibung TEXT,
  preis DECIMAL(10,2),
  kategorieId INT UNSIGNED NOT NULL,   -- FK-Datentyp muss zum Parent passen (inkl. UNSIGNED)
  INDEX idx_artikel_name (artikelName),
  CONSTRAINT artikel_kategorie
    FOREIGN KEY (kategorieId)
    REFERENCES kategorie (kategorieId)
    ON UPDATE CASCADE
    ON DELETE NO ACTION
);
Was passiert bei: DELETE FROM kategorie WHERE kategorieId = 3;▶

Fehler! ON DELETE NO ACTION blockiert: Maus und Tastatur verweisen auf Kategorie 3.

Zusatz: Kategorie 4 (Kabel) waere loeschbar — kein Artikel verweist darauf.

Merksatz: "NO ACTION = Datenbank schuetzt abhaengige Datensaetze."

Was passiert bei: UPDATE kategorie SET kategorieId = 30 WHERE kategorieId = 3;▶

Klappt: ON UPDATE CASCADE aendert die kategorieId bei Maus und Tastatur automatisch auf 30 mit.

Merksatz: "CASCADE = Aenderung wandert zum Child."

Warum muss beim Befuellen zuerst kategorie, dann artikel befuellt werden?▶

Der FK-Wert muss beim INSERT bereits im Parent existieren, sonst Constraint-Fehler.

Merksatz: "Erst Parent, dann Child — Loeschen umgekehrt."

Struktur nachtraeglich aendern — ALTER, Indizes, Tabellen kopieren und leeren:

Fuege der Tabelle artikel eine Spalte lagerbestand direkt nach preis hinzu.▶ 
ALTER TABLE artikel
  ADD COLUMN lagerbestand INT UNSIGNED NOT NULL DEFAULT 0 AFTER preis;
-- FIRST statt "AFTER preis" setzt die Spalte an die erste Position

Merksatz: "ADD COLUMN ... AFTER spalte / FIRST steuert die Position."

Aendere beschreibung auf VARCHAR(255) mit Standardwert.▶ 
ALTER TABLE artikel
  MODIFY beschreibung VARCHAR(255) NOT NULL DEFAULT '(keine)';

Typischer Fehler: MODIFY braucht die komplette neue Definition — fehlt NOT NULL, ist die Spalte danach wieder nullable.

Merksatz: "MODIFY = Definition tauschen, Spaltenname bleibt."

Benenne artikelName in bezeichnung um und mach sie zu VARCHAR(100).▶ 
ALTER TABLE artikel
  CHANGE COLUMN artikelName bezeichnung VARCHAR(100) NOT NULL;

Typischer Fehler: CHANGE mit MODIFY verwechseln — MODIFY kann nicht umbenennen. Reihenfolge: alter Name, neuer Name, dann die Definition.

Merksatz: "CHANGE = umbenennen + neu definieren, MODIFY = nur neu definieren."

Loesche beschreibung und lagerbestand in einem Statement.▶ 
ALTER TABLE artikel
  DROP COLUMN beschreibung,
  DROP COLUMN lagerbestand;

Merksatz: "Mehrere Aenderungen in einem ALTER — per Komma trennen."

Fuege den Fremdschluessel artikel → kategorie nachtraeglich hinzu.▶ 
ALTER TABLE artikel
  ADD CONSTRAINT artikel_kategorie
  FOREIGN KEY (kategorieId) REFERENCES kategorie (kategorieId)
  ON UPDATE CASCADE
  ON DELETE NO ACTION;

Typischer Fehler: vorhandene Daten verletzen den FK — verweist eine kategorieId in artikel auf keinen Parent, scheitert das ADD CONSTRAINT.

Merksatz: "FK nachruesten = ADD CONSTRAINT ... FOREIGN KEY ... REFERENCES ..."

Lege einen Index auf preis an, entferne ihn wieder, zeige alle Indizes.▶ 
ALTER TABLE artikel ADD INDEX idx_preis (preis);
ALTER TABLE artikel DROP INDEX idx_preis;
SHOW INDEX FROM artikel;

Merksatz: "Index = Register fuers schnelle Suchen/Sortieren — kostet aber beim Schreiben Zeit."

Welche vier Index-Arten gibt es — und ist ein Fremdschluessel ein Index?▶

1. PRIMARY KEY — eindeutig und nicht NULL, genau einer pro Tabelle.

2. UNIQUE — eindeutig, NULL ist (einmal) erlaubt.

3. Normaler INDEX — nur Tempo, Duplikate erlaubt.

4. Fremdschluessel — ist eine Regel (referentielle Integritaet), kein eigener Index-Typ. Zum schnellen Pruefen braucht er aber einen Index auf der Spalte; MariaDB legt ihn automatisch an, falls keiner existiert.

Randnotiz: Standard-Indexstruktur ist BTREE (gut fuer Bereich/Sortierung); daneben gibt es FULLTEXT (Volltext) und SPATIAL (Geodaten).

Merksatz: "PK und UNIQUE sind auch Indizes — der FK ist eine Regel, die einen Index nutzt."

Struktur kopieren: CREATE TABLE ... LIKE vs. ... AS SELECT.▶ 
CREATE TABLE artikel_backup LIKE artikel;
-- exakte Struktur (Spalten, Indizes, Keys, AUTO_INCREMENT), 0 Zeilen

CREATE TABLE artikel_backup AS SELECT * FROM artikel;
-- Struktur + alle Daten, aber OHNE Schluessel/Indizes/AUTO_INCREMENT

Merksatz: "LIKE = leere Kopie mit Schluesseln, AS SELECT = gefuellte Kopie ohne Schluessel."

Wie leerst du bestellung komplett — und wie grenzt sich das von DELETE und DROP ab?▶ 
TRUNCATE TABLE bestellung;

Loescht alle Datensaetze, die Tabellenstruktur bleibt, AUTO_INCREMENT wird auf 1 zurueckgesetzt.

Abgrenzung:

DELETE FROM bestellung; (ohne WHERE) — leert ebenfalls, aber Zeile fuer Zeile (DML, per ROLLBACK widerrufbar, Zaehler laeuft weiter).

DROP TABLE bestellung; — entfernt die Tabelle inklusive Struktur; danach ist sie weg.

Merksatz: "TRUNCATE leert (schnell, Zaehler-Reset), DELETE loescht Zeilen (widerrufbar), DROP wirft die Tabelle weg."

Warum scheitert CREATE TABLE position (...) — und wie loest du es?▶

position (wie auch order, group, rank) ist ein reserviertes Wort — ohne Schutz kommt ein Syntaxfehler.

CREATE TABLE `position` (
  id INT UNSIGNED NOT NULL PRIMARY KEY,
  `rank` INT
);

Typischer Fehler: reservierte Woerter als Tabellen-/Spaltennamen ohne Backticks.

Merksatz: "Reserviertes Wort als Name? In Backticks setzen: `position`."

SELECT k.bezeichnung, SUM(a.preis) AS gesamt
FROM kategorie k
INNER JOIN artikel a ON k.kategorieId = a.kategorieId

🔍 Filtern & Sortieren — LIKE, DISTINCT, ORDER BY, UNION
Alle Artikel, deren Name mit T beginnt — und alle, die 'us' enthalten.▶ 
SELECT artikelName FROM artikel WHERE artikelName LIKE 'T%';
-- Tastatur
SELECT artikelName FROM artikel WHERE artikelName LIKE '%us%';
-- Maus

Merksatz: "% = beliebig viele Zeichen, _ = genau ein Zeichen."

Trick: Ein fester Text ('KUNDE') als erste Spalte stempelt jeder Zeile ihre Herkunft auf — typisch, wenn zwei Quellen (z. B. Kunden und Lieferanten) zusammengefuehrt werden.

Typischer Fehler: unterschiedliche Spaltenzahl/-reihenfolge in den beiden SELECTs — bei UNION muessen Anzahl und Typen der Spalten zusammenpassen.

Merksatz: "Literal-Spalte = Herkunftsstempel; beide SELECTs brauchen dieselbe Spaltenstruktur."

DISTINCT ueber zwei Spalten — einmalige Kombinationen.▶ 
SELECT DISTINCT plz, ort FROM kunde_adresse;

Wirkung: DISTINCT bezieht sich auf die ganze Zeile, nicht auf eine einzelne Spalte — hier bleibt jede Kombination aus plz und ort genau einmal uebrig. Dieselbe PLZ mit zwei verschiedenen Orten ergibt also zwei Zeilen.

Beispiel abstrakt: Die Webshop-DB dieser Seite hat keine Adressspalten — das Muster gilt fuer jede Tabelle.

Typischer Fehler: DISTINCT als Funktion auf nur eine Spalte beziehen (DISTINCT(plz), ort) — es wirkt immer auf alle SELECT-Spalten zusammen.

Merksatz: "DISTINCT gilt fuer die komplette Zeile, nicht fuer eine Klammer."

🔐 Rechte vergeben — GRANT & REVOKE
Ein Azubi-Account soll die webshop-DB nur lesen und Datensaetze einfuegen duerfen.▶ 
GRANT SELECT, INSERT ON webshop.* TO 'azubi'@'localhost';

Merksatz: "GRANT rechte ON datenbank.tabelle TO nutzer."

Das Einfuegen soll wieder entzogen werden.▶ 
REVOKE INSERT ON webshop.* FROM 'azubi'@'localhost';

Typischer Fehler: TO statt FROM — GRANT ... TO, aber REVOKE ... FROM.

Warum bekommt der Azubi nicht einfach ALL PRIVILEGES?▶

Least-Privilege-Prinzip — jeder Account erhaelt nur die Rechte, die er fuer seine Aufgabe braucht. Begrenzt Schaden bei Fehlbedienung und kompromittierten Konten (Bruecke zu LF4 / IT-Grundschutz).
