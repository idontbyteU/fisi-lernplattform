SQLite3 in Python — vom Verbinden bis zum Ergebnis

Der komplette Datenbankzugriff mit SQLite3 in Python auf einer Seite: Verbindung aufbauen, Tabellen anlegen, Daten schreiben und lesen, Ergebnisse verarbeiten und sicher mit Parameterbindung, NULL/None und datetime arbeiten.

→ Uebungen → Pruefungs-SQL (MariaDB)
🛠️ Zugriff vorbereiten

Verbindung aufbauen, Cursor holen und eine Tabelle anlegen:

import sqlite3

db = sqlite3.connect("datenbank.sqlite3")   # Datei-DB (wird bei Bedarf angelegt)
db = sqlite3.connect(":memory:")            # DB im RAM, nicht persistent

cursor = db.cursor()
sql = "CREATE TABLE tblArtikel(id INTEGER PRIMARY KEY AUTOINCREMENT, Name TEXT, Anzahl INTEGER, Preis REAL)"
cursor.execute(sql)
db.close()
💡
Tipp: Der grafische SQLite-Editor sqlitebrowser.org hilft beim einfachen Anlegen und Ansehen von Tabellen.
🧩 Das Komplettbeispiel

Ein durchgehendes Skript — alle folgenden Abschnitte erklären die einzelnen Bausteine daraus:

import sqlite3
# 1. Verbindung und Cursor erstellen
db = sqlite3.connect("datenbank.sqlite3")
cursor = db.cursor()
# 2. Tabelle anlegen
sql_create = """CREATE TABLE schueler (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    alterj INTEGER,
    klasse TEXT
)"""
cursor.execute(sql_create)
# 3. Daten eintragen (und speichern!)
cursor.execute("INSERT INTO schueler (name, alterj, klasse) VALUES ('Anna', 27, 'FI2027')")
cursor.execute("INSERT INTO schueler (name, alterj, klasse) VALUES ('Hans', 22, 'FI2027')")
db.commit()
# 4. Daten abfragen und formatiert ausgeben
cursor.execute("SELECT * FROM schueler WHERE id < 5 ORDER BY id DESC")
for ds in cursor:
    print(f"{ds[0]:2} {ds[1]:6} {ds[2]:3} {ds[3]:8}")
# 5. Verbindung schliessen
db.close()
🗄️ Die Datenbank-Befehle (sqlite3)
connect("datenbank.sqlite3")
öffnet die Datenbankdatei. Existiert sie nicht, wird sie bei Bedarf automatisch erstellt.
db.cursor()
liefert den Cursor. Bild dazu: db ist die Telefonleitung zur Datenbank, der cursor ist die Person, der du am anderen Ende deine Befehle diktierst.
cursor.execute(...)
führt einen SQL-Text aus (Tabelle anlegen, einfügen, abfragen …).
db.commit()
Änderungen liegen zunächst nur im Zwischenspeicher (in der laufenden Transaktion). Erst commit() schreibt sie dauerhaft auf die Platte.
db.close()
gibt die Datei wieder frei. Gehört zum sauberen Programmieren dazu.
⚠️
Achtung: commit() vergessen = Skript läuft fehlerfrei durch, aber nach close() ist nichts gespeichert.
📌
Merke: Daten ändern (INSERT/UPDATE/DELETE) → committen. Nur lesen (SELECT) → kein commit nötig. CREATE speichert SQLite sofort.
✏️ Schreiben: INSERT / UPDATE / DELETE + commit()
import sqlite3

db = sqlite3.connect("datenbank.sqlite3")
cursor = db.cursor()
sql = "INSERT INTO tblArtikel (Name, Anzahl) VALUES('Hut',14)"
cursor.execute(sql)
db.commit()   # Bestaetigt die Speicherung!
db.close()
⚠️
Merkregel: Fuer INSERT, UPDATE und DELETE ist commit() notwendig – sonst werden die Daten NICHT gespeichert.
📖 Lesen: SELECT, fetchall() & Cursor
SELECT
cursor = db.cursor()
cursor.execute("SELECT * FROM tblArtikel")
for ds in cursor:
    print(f"{ds[0]:4} {ds[1]:12} {ds[2]:5}")
💡
Hinweis: SELECT * FROM sqlite_master liefert das Schema der Datenbank (welche Tabellen es gibt).
fetchall() – Ergebnis in eigene Liste
cursor.execute("SELECT * FROM tblArtikel")
data = cursor.fetchall()   # ganzes Ergebnis in Variable
db.close()                 # DB kann sofort geschlossen werden

for ds in data:
    print(f"{ds[0]:4} {ds[1]:12} {ds[2]:8.2f}")

Vorteil: Die Datenbank ist sofort schliessbar und der Fehler Unread result found wird vermieden.

Der Datenbank-Cursor

Erst die Verbindung (Connection) ueber connect(), dann den Cursor ueber db.cursor(). Der Cursor sendet SQL (execute) und nimmt Ergebnisse entgegen.

  • Ergebnis durchlaufen mit for ds in cursor: oder – besser – data = cursor.fetchall()
  • cursor.rowcount = Anzahl betroffener Datensaetze (bei SELECT in SQLite3 nicht verfuegbar)
🔁 Ergebnisse verarbeiten (for-Schleife)
for ds in cursor:
holt jede Ergebniszeile einzeln ab und legt sie in ds.
Datensatz = Tupel (Index ab 0)
Ein Datensatz ist ein Tupel, z. B. (1, 'Anna', 27, 'FI2027'). Der Index startet bei 0: ds[0]=id, ds[1]=name, ds[2]=alterj, ds[3]=klasse.
f-Strings & Formatbreite
f-Strings setzen Variablen direkt in geschweifte Klammern {} ein. Die Formatbreite wie {ds[0]:2} reserviert mindestens 2 Zeichen Platz — so stehen die Spalten in der Konsole gerade untereinander.
📌
Merke: SELECT liefert Tupel — Zugriff per Index, Zählung startet bei 0.
🔐 Sicher & Speziell
Parameterbindung (Platzhalter ?)
sql = "INSERT INTO tblArtikel (Name, Anzahl) VALUES (?,?)"
cursor.execute(sql, [n, a])
📌
Vorteile der Parameterbindung: einfacher & lesbarer · Schutz vor SQL-Injection · korrekte Typuebergabe · bessere Performance bei Massenoperationen.
NULL / None

NULL aus der Datenbank wird in Python zu None. None geht nicht direkt in einen f-String – vorher in einen Leerstring umwandeln. Ein Datensatz ist oft ein Tupel (unveraenderbar), daher erst in eine Liste wandeln:

daten = cursor.fetchall()
for ds in daten:
    ds = list(ds)
    if ds[2] is None: ds[2] = ""
    print(f"{ds[0]:5} {ds[2]:10}")
Modul datetime (Datum & Zeit)
import datetime

zeit  = datetime.time(13, 34, 22)              # Uhrzeit
datum = datetime.date(1912, 6, 23)             # Datum
mond  = datetime.datetime(1969, 7, 21, 3, 56)  # Datum + Zeit
jetzt = datetime.datetime.now()

diff  = ziel - jetzt   # Subtraktion zweier datetime -> timedelta
  • Objekte: date / time / datetime; timedelta fuer Differenzen
  • Zeitbereich: 01.01.0001 – 31.12.9999
📌
Kurz gemerkt: Verbindung → Cursor → execute(). Zum Schreiben immer commit(), zum Lesen gern fetchall(). Werte immer ueber Platzhalter (?) uebergeben – nie per String-Zusammenbau.
🧠 Teste dich
Was passiert, wenn du db.commit() nach einem INSERT weglässt?
Die Änderungen bleiben in der Transaktion (Zwischenspeicher) und gehen mit close() verloren — es wird nichts dauerhaft gespeichert.
Was steht in ds[2] beim Datensatz (1, 'Anna', 27, 'FI2027')?
27 — die Zählung beginnt bei 0, also ist ds[2] das dritte Element (alterj).
Warum heißt die Spalte alterj und nicht alter?
alter ist ein reserviertes SQL-Schlüsselwort (ALTER TABLE) — als Spaltenname würde es zu Problemen führen.
