LF 5SQL-Syntax Schritt für Schritt

Satzzeichen im SQL-Code · ; ( ) , ` '

Anhand der Webshop-Aufgabe (CREATE TABLE + INSERT in MariaDB): Was bedeutet jedes Satzzeichen im SQL-Code — und warum steht `position` in Backticks?

1 Semikolon — wo eine Anweisung endet

SQL ignoriert Zeilenumbrüche komplett. Eine Anweisung ist erst zu Ende, wenn das ; kommt. Deshalb kann sich ein CREATE TABLE über 15 Zeilen erstrecken und zählt trotzdem als eine Anweisung. 

CREATE DATABASE webshop;
USE webshop;

In HeidiSQL wichtig: Beim Ausführen mit F9 nutzt HeidiSQL die Semikolons, um das Skript in einzelne Anweisungen zu zerlegen. USE webshop; bedeutet: „Alle folgenden Befehle beziehen sich auf diese Datenbank" — sonst müsste man überall webshop.kunde schreiben.

2 Kommentare

-- Kommentar bis zum Zeilenende (zwei Minus + Leerzeichen!)
/* Mehrzeiliger
   Kommentar */

MariaDB überliest beides komplett — gleiche Logik wie # in Python.

3 CREATE TABLE — Klammern und Kommas

Das äußere Klammernpaar ( … ) umschließt die komplette Spaltendefinition. Darin trennt das , die einzelnen Einträge — jeder Eintrag ist entweder eine Spalte oder ein Constraint. 

CREATE TABLE kunde (
    kundeId  INT UNSIGNED NOT NULL AUTO_INCREMENT,
    vorname  VARCHAR(50) NOT NULL,
    PRIMARY KEY (kundeId)   -- letzter Eintrag: KEIN Komma!
);

Eine Spaltendefinition liest sich immer gleich: Name → Datentyp → Optionen. Klassischer Anfängerfehler: ein Komma nach dem letzten Eintrag vor der schließenden Klammer → Syntaxfehler.

4 Die Klammer beim Datentyp bedeutet je nach Typ etwas anderes

VARCHAR(50) — maximale Länge, variabel

Bis zu 50 Zeichen. „Max" belegt nur 3 Zeichen Speicher.

CHAR(5) — feste Länge (und warum PLZ kein INT ist)

Immer genau 5 Zeichen — perfekt für die PLZ.

Warum kein INT? Weil 01067 (Dresden) als Zahl die führende Null verlieren würde. PLZs sind Zeichenketten — man rechnet nicht damit.

DECIMAL(10,2) — zwei Zahlen in der Klammer

10 Stellen insgesamt, davon 2 nach dem Komma → maximal 99999999.99.

Für Geldbeträge Pflicht: FLOAT produziert Rundungsfehler (0.1 + 0.2 = 0.30000000000000004 — kennst du aus Python).

ENUM('offen', …) — Liste erlaubter Werte

Die Klammer enthält alle erlaubten Werte, durch Kommas getrennt. Jeder andere Wert wird abgelehnt — quasi ein eingebauter Constraint.

INT / TEXT — keine Klammer

Brauchen keine Längenangabe.

5 Die drei Anführungszeichen — der Kern der Sache

ZeichenJobBeispiel
` ` Backticks Namen (Tabellen, Spalten). Nötig bei Kollision mit Schlüsselwörtern oder Sonderzeichen im Namen. CREATE TABLE `position`
' ' einfach Werte: Strings und Daten. Das ist der SQL-Standard. 'Max', 'versendet', '2025-11-04'
" " doppelt Finger weg. Verhält sich je nach Servereinstellung (ANSI_QUOTES) mal wie ', mal wie ` — also unzuverlässig. —

Warum braucht position Backticks? POSITION() ist eine eingebaute String-Funktion in MariaDB (POSITION('b' IN 'abc') → 2). Ohne Backticks weiß der Parser nicht, ob Funktion oder Tabellenname gemeint ist → Syntaxfehler. Mit Backticks ist es eindeutig: ein Name.

Merksatz: Backticks = „das heißt so" · einfache Quotes = „das steht drin"

Deutsche Tastatur: Backtick liegt neben dem ß → Shift + ´, dann Leertaste.

6 Zeichen für Zeichen: der FK-Constraint

👆 Tippe/klicke die unterstrichenen Teile an — die Erklärung erscheint darunter.

CREATE TABLE `position` (
    positionId   INT UNSIGNED NOT NULL AUTO_INCREMENT,
    anzahl       INT,
    artikelId    INT UNSIGNED NOT NULL,
    bestellungId INT UNSIGNED NOT NULL,
    PRIMARY KEY (positionId),
    CONSTRAINT fk_position_artikel
        FOREIGN KEY (artikelId) REFERENCES artikel(artikelId)
);
Noch nichts ausgewählt — tippe oben ein markiertes Element an.

7 INSERT — die zwei Klammernpaare

INSERT INTO kunde (vorname, nachname, mail) VALUES
('Max', 'Müller', 'max.mueller@example.com'),
('Laura', 'Schmidt', 'laura.schmidt@example.com');

Erstes Klammernpaar (nach dem Tabellennamen): welche Spalten befüllt werden — in welcher Reihenfolge. AUTO_INCREMENT- und DEFAULT-Spalten lässt man einfach weg.

Nach VALUES: pro Datensatz ein Klammernpaar. Die Werte müssen exakt zur Spaltenliste passen — gleiche Anzahl, gleiche Reihenfolge. Zwischen den Datensätzen , — nach dem letzten das ;.

Spezialfall '' — leerer String ≠ NULL

Zwei einfache Quotes direkt hintereinander = leerer String.

Leerer String heißt „da steht was, nämlich nichts". NULL heißt „unbekannt / kein Wert". Die Aufgabe verlangt bei der Tastatur explizit den leeren String.

Spezialfall DEFAULT — ohne Quotes!

('2025-11-13', DEFAULT, 1) — das Schlüsselwort DEFAULT sagt: „Setz den Default-Wert aus der Tabellendefinition ein" → hier 'offen'.

Mit Quotes ('DEFAULT') würde MariaDB versuchen, den String „DEFAULT" in die ENUM-Spalte zu stecken → Fehler, weil er nicht in der Werteliste steht.

Datumsformat

Immer 'JJJJ-MM-TT' (ISO 8601) in einfachen Quotes: '2025-11-04'. Das deutsche Format '04.11.2025' funktioniert nicht.

Logische Auswertungsreihenfolge: FROM → WHERE (einzelne Zeilen) → GROUP BY → HAVING (fertige Gruppen) → SELECT → ORDER BY → LIMIT. Deshalb ist WHERE COUNT(*) > 1 ein Fehler: COUNT existiert an dieser Stelle noch nicht.
position ist zweideutig: Als Tabellenname reserviert-nah, daher Backticks: CREATE TABLE `position`. Als String-Funktion: SELECT POSITION('shop' IN 'webshop') liefert 4 — SQL zählt ab 1, nicht ab 0 wie Python.

Erst selbst beantworten (laut oder auf Papier), dann Lösung aufklappen.

1. Warum steht `position` in Backticks — und was würde ohne passieren?

Lösung

POSITION() ist eine eingebaute MariaDB-Funktion. Ohne Backticks kann der Parser Funktion und Tabellenname nicht unterscheiden → Syntaxfehler. Backticks markieren das Wort eindeutig als Namen.

2. Welche drei Anführungszeichen gibt es in SQL und wofür?

Lösung

` Backticks für Namen · ' einfache Quotes für Werte (Strings, Daten) · " doppelte Quotes vermeiden (Verhalten hängt von ANSI_QUOTES ab).

3. Was ist der Unterschied zwischen '' und NULL?

Lösung

Leerer String = ein vorhandener Wert mit Länge 0 („da steht nichts drin"). NULL = kein Wert / unbekannt. Ein NOT NULL-Constraint erlaubt '', aber kein NULL.

4. Warum DEFAULT ohne Quotes schreiben?

Lösung

Es ist ein Schlüsselwort („nimm den Default-Wert der Spalte"), kein String. 'DEFAULT' mit Quotes wäre der Text „DEFAULT" — der steht nicht in der ENUM-Liste → Fehler.

5. Warum ist plz CHAR(5) und nicht INT?

Lösung

PLZs können mit 0 beginnen (01067 Dresden) — als Zahl ginge die führende Null verloren. Außerdem rechnet man mit PLZs nicht. CHAR(5), weil PLZs immer genau 5 Zeichen haben.

6. In welcher Reihenfolge müssen die 5 Webshop-Tabellen erstellt werden — und warum?

Lösung

Erst kunde und kategorie (keine FKs), dann artikel (→ kategorie) und bestellung (→ kunde), zuletzt `position` (→ artikel + bestellung). REFERENCES schlägt fehl, wenn die Zieltabelle noch nicht existiert. Gleiche Reihenfolge gilt für die INSERTs.

7. Transferaufgabe: Schreib die Tabelle `position` aus dem Kopf — inkl. beider FKs.

Lösung 
CREATE TABLE `position` (
    positionId   INT UNSIGNED NOT NULL AUTO_INCREMENT,
    anzahl       INT,
    artikelId    INT UNSIGNED NOT NULL,
    bestellungId INT UNSIGNED NOT NULL,
    PRIMARY KEY (positionId),
    CONSTRAINT fk_position_artikel
        FOREIGN KEY (artikelId) REFERENCES artikel(artikelId),
    CONSTRAINT fk_position_bestellung
        FOREIGN KEY (bestellungId) REFERENCES bestellung(bestellungId)
);
